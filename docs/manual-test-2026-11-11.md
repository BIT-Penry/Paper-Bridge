## 发现并修复的问题

首次导入时，新笔记的 metadataCache 可能尚未建立。旧实现根据缓存中的“导入日期”判断图片目录，导致新论文主图误放到 `标题-assets/images/`。

修复为：新导入使用调用时已有的导入上下文判断目录，图片直接写入论文的 `images/`；手动处理旧扁平笔记时继续使用独立附件目录。已新增空 metadataCache 回归测试，并在真实仓库中重新导入验证通过。首次运行的文件已保留在测试库回收目录，未混入最终示例。

## 边界与未测项目

- 这不是所有出版社、操作系统或 Obsidian 版本的兼容性保证。
- 本轮未进行真实付费 API 翻译、IEEE 出版社下载、本地 PDF 补入和无 HTML 论文等端到端测试。
- 翻译、钥匙串、HTTP 失败、同名目录保护等分支已通过离线测试；不等同于真实服务验证。
- 测试库保留 NavRL 粗读示例、DiffDreamer 精读示例及自定义目录设置，可继续手动检查。

## 原生精简界面验证

同日在上述独立测试库更新插件并重新启用，使用 Obsidian 原生深色主题检查：

- 设置分组、现有自定义目录和默认精读保留；翻译关闭时服务配置隐藏。
- 导入窗口优先显示来源与阅读深度；保存目录、翻译状态可见，可选来源默认收起。
- 无效输入保留，输入框标记错误，窗口内显示明确失败原因。
- 展开补充来源后可见 DOI、PDF 直链和本地文件选择，长表单可滚动。
- 离线行为测试覆盖空输入禁用、纠正输入、回车提交、忙碌状态防重复提交和设置交互。

本次界面调整未重新执行两篇论文的网络下载；上述真实导入记录来自调整前的同日验证。未实机验证浅色主题、窄屏或真实翻译服务。
